# Вместе — один файл для вашего вечера

Всё приложение находится в **`index.php`**: интерфейс, мобильная вёрстка, стили, JavaScript, чат и PHP API. Папки `public`, `assets`, `src`, Composer, Node.js и отдельная установка базы не нужны.

## Установка на shared-хостинге

1. Скачайте `dist/vmeste-php.zip` и распакуйте на компьютере.
2. В панели хостинга выберите PHP **8.2 или новее**. Расширения **pdo_sqlite** и **mbstring** должны быть включены.
3. Загрузите **только `index.php`** в корневую папку сайта. Если корень уже настроен на `public`, загрузите файл прямо в эту `public`. Если корень указывает на каталог домена — положите файл туда. Перенастраивать корень сайта больше не требуется.
4. Откройте сайт по HTTPS. Обновите страницу через Ctrl + Shift + R.

Для существующей установки достаточно заменить `index.php` именно в текущем корне сайта. Старые `assets`, `src`, `scripts` и `tests` новой версии не нужны, но удалять свои данные для обновления не требуется. ZIP, README и исходные папки не нужно загружать на хостинг.

Если после загрузки виден PHP-код, а не сайт, остановитесь и включите обработку PHP для домена в панели. Если показано сообщение про расширения — включите их в настройках PHP.

## Как смотреть

Введите ник → создайте зал → «Пригласить» → отправьте ссылку девушке. Она открывает эту ссылку и вводит свой ник. Добавьте ссылку YouTube и нажмите ▶. Пауза и перемотка общие, чат рядом. На телефоне чат открывается поверх страницы кнопкой «Чат» рядом с плеером.

Браузер может потребовать нажатие «Включить у меня» для запуска со звуком на каждом устройстве. YouTube должен быть доступен вам обоим; видео должно разрешать встраивание. API-ключи не нужны.

Ссылка даёт доступ к залу и управлению видео — отправляйте её лично. Один браузерный профиль считается одним участником, поэтому для проверки вдвоём используйте два устройства или приватное окно.

## Что нового для ваших вечеров

- **Очередь:** добавляйте YouTube и прямые MP4/WebM-ссылки, меняйте порядок стрелками, перемешивайте, выбирайте случайное видео. Следующий ролик автоматически запускается после окончания текущего. Кнопка «Следующее видео» переключает вручную и оставляет видео на паузе до общего старта.
- **«Жду тебя»:** пауза с сохранением позиции и отдельной готовностью каждого. После подтверждения минимум двух присутствующих участников просмотр продолжается, если до ожидания видео играло. «Отменить ожидание» снимает ожидание и оставляет паузу. В зале для двоих достаточно, чтобы каждый нажал «Я готов / готова».
- **Реакции:** сердце, смех, удивление и другие реакции видны обоим поверх видео. Уважается системная настройка уменьшения анимации.
- **Наши моменты:** сохраните таймкод с подписью, затем вернитесь к нему одним нажатием. Закладка помнит видео, а не только секунду.
- **История вечеров:** последние 100 запусков сгруппированы по локальной дате устройства; любое видео можно запустить снова. Названия задаются вами при добавлении — ключ YouTube API не нужен.
- **Режим кино:** более крупный плеер, скрытая шапка, переключение чата и полноэкранный просмотр. Поддержка fullscreen зависит от браузера; режим кино остаётся доступным на телефоне. Мобильный чат открывается отдельной панелью и закрывается крестиком.
- **«Выбирай ты»:** передайте выбор следующего видео второму участнику или верните общий выбор. Пауза и перемотка остаются общими. Если выбранный участник ушёл, общий выбор можно восстановить. Оба по-прежнему могут предлагать видео в очередь.
- **Свой плеер:** единая панель с общей перемоткой/паузой и локальной громкостью. YouTube играет через официальный IFrame API. Прямые HTTPS-ссылки на `.mp4` и `.webm` воспроизводятся HTML5-плеером, без загрузки или перекодирования на хостинге. Источник должен быть доступен обоим и поддерживать формат браузера; для стабильной перемотки ему нужны HTTP Range-запросы. Временные ссылки могут истечь. Загрузка видеофайлов и субтитров на сервер не реализована.
- **Голос:** каждый нажимает «Включить микрофон» и разрешает доступ браузеру. Можно выключить свой микрофон, пересоединиться или полностью завершить разговор. Видео приглушается на время соединённого разговора. Лучше использовать наушники.

## Голосовая связь и TURN

Голос рассчитан на двоих и требует HTTPS (кроме локальной разработки). PHP передаёт offer/answer и ICE-кандидаты через обычные запросы, WebSocket и фоновые процессы не нужны. Сам звук передаётся WebRTC, не записывается PHP и не сохраняется в SQLite. При выходе микрофон останавливается.

По умолчанию указан Google STUN. **STUN не гарантирует соединение между любыми сетями.** Если NAT, мобильный оператор или корпоративная сеть мешают прямому соединению, нужен доступный обоим TURN-сервер. Интерфейс сообщает о неудаче и предлагает пересоединиться; установка приложения на shared-хостинг не создаёт TURN автоматически.

При наличии своего TURN укажите его в константе `VMESTE_ICE_SERVERS` в начале `index.php`:

```php
const VMESTE_ICE_SERVERS = [
    ['urls' => 'stun:stun.l.google.com:19302'],
    [
        'urls' => ['turn:turn.example.com:3478', 'turns:turn.example.com:5349'],
        'username' => 'YOUR_TURN_USERNAME',
        'credential' => 'YOUR_TURN_CREDENTIAL',
    ],
];
```

Также можно задать `WATCH_ICE_SERVERS` в формате JSON — он имеет приоритет над константой. Указанные имена и значения в примере — заглушки, их нужно заменить своими. TURN-данные получают браузеры участников зала; используйте ограниченные или временные учётные данные. Пароли хостинга или SSH сюда не подходят. Вкладка сообщает о разрыве голоса и даёт кнопку пересоединения; после отключения от сервера дольше 20 секунд может потребоваться включить голос снова.

## Данные

SQLite создаётся автоматически в отдельном каталоге `vmeste-…` во временной папке PHP **вне каталога сайта**. Создавать папки и выставлять права на каталог сайта не требуется. PHP должен иметь доступ на запись во временную папку и каталог сессий — обычно хостинг уже это обеспечивает.

Чат и состояние сохраняются между запросами и перезапусками PHP, пока хостинг не очистит временные файлы. Для просмотра на пару вечеров этого достаточно; долговременное хранение истории не гарантируется. При необходимости постоянного хранения администратор может задать `WATCH_DB` — абсолютный путь к SQLite вне публичного каталога, в существующей доступной на запись папке.

Обновление файла по тому же пути сохраняет данные. Перенос на другой путь создаёт отдельное хранилище; история предыдущей многофайловой версии автоматически не переносится.

## Что сохранено

Серверное состояние видео с версией команды, общая пауза и перемотка, исправление расхождения более 1,5 секунды, автоматическое переподключение, последние 300 сообщений, CSRF-защита, безопасный вывод текста, ограничения частоты запросов. Новые таблицы и поля добавляются автоматически с сохранением существующей базы. Стили и скрипты встроены с CSP nonce, поэтому отдельные CSS/JS-файлы больше не могут потеряться при загрузке.

Сверка состояния происходит примерно раз в секунду, в фоновой вкладке — раз в четыре. Это не покадровая синхронизация. Прямые эфиры, YouTube-плейлисты, реклама, платный контент и ограничения YouTube не синхронизируются и не обходятся. Очередь приложения состоит из отдельных видео. Встраивание реального YouTube требуется проверить на ваших устройствах: в cloud-окружении доступ к нему блокирует сетевой прокси.

## Разработка и проверки

На Debian 13 в cloud можно подготовить PHP командой `bash scripts/setup-cloud.sh`. Для обычного PHP это не требуется.

```sh
PHP_BIN=/workspace/php-runtime/bin/php python3 tests/integration.py
```

Тесты запускают отдельный сервер и копируют в пустой каталог **только `index.php`**. Проверяются чат, независимые сессии, пауза, перемотка, повторный просмотр, поздний вход, конфликт команд, очередь, ожидание готовности, закладки и история, передача выбора, реакции, валидация, изоляция голосовых сигналов и миграция старой базы.

Для ручного запуска копируйте `index.php` в отдельный пустой каталог и запускайте оттуда встроенный PHP-сервер. Он предназначен для разработки, на shared-хостинге запускает PHP сам веб-сервер.

Опциональная браузерная проверка (Playwright и Chromium нужны только для теста):

```sh
BASE_URL=http://127.0.0.1:8081 CHROMIUM_PATH=/usr/bin/chromium node tests/browser.cjs
```

Тест проверяет два браузера, мобильную вёрстку, восстановление сети, новые функции, реальное HTML5-воспроизведение тестового WebM, обмен WebRTC-сигналами и управление искусственными микрофонами. По умолчанию тест также требует установленного голосового соединения. В управляемом cloud-браузере политика `WebRtcIPHandling=disable_non_proxied_udp` блокирует голосовой транспорт. Для проверки этого известного ограничения запускайте тест с `VOICE_TRANSPORT_EXPECTED_BLOCKED=1`: он проверит offer/answer и сообщение о неудаче, но явно выведет, что звук не проверен. Отключать эту политику для обхода сетевых ограничений не нужно. YouTube заменён тестовым адаптером. Это не подтверждает доступность реального YouTube, слышимость реальных микрофонов или проходимость NAT между вашими устройствами. Тестовый WebM с цветной таблицей и синусоидальным звуком сгенерирован FFmpeg и не содержит чужих материалов. При размещении в подпапке укажите её в BASE_URL, например `http://127.0.0.1:8081/pair/`.
