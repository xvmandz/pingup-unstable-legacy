# Вместе — личный зал для YouTube

PHP-приложение для совместного просмотра: вход по нику, приглашение по ссылке, общий плеер и чат. Без регистрации, Composer, сборщика и API-ключа YouTube. Интерфейс на русском, работает на телефоне и компьютере.

## Как пользоваться

1. Откройте сайт, введите ник и создайте зал.
2. Нажмите «Пригласить», скопируйте ссылку и отправьте её лично второму участнику.
3. Второй участник открывает **эту же ссылку**, вводит свой ник и входит.
4. Вставьте ссылку на видео YouTube и нажмите «Смотреть». Видео подготовится на обоих устройствах. Нажмите ▶, чтобы начать для всех.
5. Пауза, запуск и перемотка общие. Громкость и разрешение на воспроизведение локальные: при блокировке автозапуска нажмите «Включить у меня» на каждом устройстве.

Ссылка — ключ к залу: любой её обладатель может войти и управлять просмотром. Паролей и роли ведущего нет. До 10 активных участников; один браузерный профиль считается одним участником. Для двух людей используйте разные устройства, профили или приватное окно.

## Требования и запуск

- PHP 8.2+ с `pdo_sqlite` и `mbstring`.
- Локальный диск для SQLite; права на запись в `var/` и в каталог PHP-сессий.
- Доступ к YouTube в браузерах участников.

Из корня репозитория:

```sh
php -m # должны присутствовать PDO, pdo_sqlite, mbstring
PHP_CLI_SERVER_WORKERS=4 php -S 0.0.0.0:8080 -t public
```

В подготовленном cloud-окружении PHP устанавливается без root:

```sh
bash scripts/setup-cloud.sh
PHP_CLI_SERVER_WORKERS=4 /workspace/php-runtime/bin/php -S 0.0.0.0:8080 -t public
```

Cloud-скрипт рассчитан на Debian 13 amd64 и существующие системные библиотеки. Он скачивает проверенные APT-пакеты в `/workspace/php-runtime`, не изменяя системный PHP. SQLite создаётся автоматически при первом запросе API. `WATCH_DB` позволяет указать другой **абсолютный** путь вне `public/`; родительский каталог должен существовать.

## Размещение на хостинге

Встроенный PHP-сервер предназначен для разработки. Для постоянного доступа используйте Nginx/Apache с PHP-FPM и HTTPS. **Document root должен указывать только на `public/`**, не на весь репозиторий. Базу, исходники и сессии нельзя отдавать как статические файлы. PHP-процессу нужны права записи в `var/`; не используйте `chmod 777`. За доверенным HTTPS-прокси настройте передачу признака HTTPS в PHP, чтобы session cookie получала Secure. Не отключайте Referrer-Policy: YouTube использует источник страницы для проверки встраивания.

Пример Nginx (пути и сокет замените на свои):

```nginx
server {
    listen 443 ssl;
    server_name watch.example.com;
    # Укажите ssl_certificate и ssl_certificate_key своего домена.
    root /srv/vmeste/public;
    index index.php;
    client_max_body_size 16k;
    add_header Referrer-Policy strict-origin-when-cross-origin always;
    location / { try_files $uri $uri/ =404; }
    location ~ ^/(index|api)\.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_param HTTPS on;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }
    location ~ \.php$ { return 404; }
    location ~ /\. { deny all; }
}
```

Обеспечьте перенаправление HTTP → HTTPS отдельно. Резервную копию работающей SQLite делайте штатным SQLite backup API/командой `.backup`, либо остановите PHP перед копированием базы и файлов WAL. Для публичного сервиса добавьте лимиты запросов и размера хранилища на уровне хостинга; приложение рассчитано на небольшие личные залы, а не массовую видеоплатформу.

## Синхронизация и восстановление

Сервер хранит идентификатор видео, позицию, флаг воспроизведения, время изменения и версию состояния. Клиенты опрашивают сервер примерно раз в секунду (раз в 4 секунды в фоновой вкладке), вычисляют текущую позицию с учётом времени ответа и исправляют расхождение более 1,5 секунды. Это синхронизация с небольшой погрешностью, не покадровый стриминг. Видео загружается непосредственно с YouTube на каждом устройстве.

Записи сериализуются транзакциями SQLite с WAL и ожиданием блокировки. Команды со старой версией отклоняются вместо перезаписи чужого действия. После потери связи опрос возобновляется автоматически, управление отключается при устаревшем состоянии. Неопределённый результат отправки показывается явно: изменяющие запросы автоматически не повторяются. После перезапуска PHP зал и чат остаются на диске. После обновления страницы снова подтвердите ник.

Активность участника истекает через 20 секунд без запросов. Хранятся последние 300 сообщений зала, клиент получает до 100 последних новых сообщений за запрос. При создании нового зала удаляются залы, в которых не было активности больше недели. Это не зашифрованный мессенджер: администратор сервера имеет доступ к SQLite.

## Безопасность и ограничения

- Случайные 128-битные ссылки, серверные сессии, CSRF-токены, HttpOnly и SameSite cookie.
- Параметризованные SQL-запросы; пользовательский текст выводится через `textContent`, а не HTML; CSP ограничивает внешние ресурсы.
- Проверяются длина текста, формат YouTube-ссылок, позиция и версия состояния. Есть ограничения частоты сообщений, команд и создания залов на сессию.
- Сервер не скачивает переданную ссылку, поэтому она не используется для произвольных HTTP-запросов.
- Поддерживаются обычные видео, `youtu.be`, `watch`, `shorts`, `embed` и `live` ссылки на записи. Синхронизация прямых эфиров/DVR, плейлисты, реклама и платный контент не поддерживаются.
- YouTube может запрещать встраивание, требовать вход, ограничивать регион или блокировать воспроизведение. Приложение показывает ошибки плеера, но не обходит эти ограничения. Фоновая вкладка и медленная сеть могут увеличивать расхождение.

## Проверки

Без сторонних Python-зависимостей:

```sh
PHP_BIN=/workspace/php-runtime/bin/php python3 tests/integration.py
# либо PHP_BIN=php на обычном хосте
node --check public/assets/app.js
```

Интеграционные проверки запускают отдельный многопроцессный PHP-сервер и временную базу: вход, чат и Unicode, CSRF, изоляция залов, конфликт одновременных команд, поздний вход в играющее видео, пауза, перемотка, повторный просмотр, валидация ссылок, ограничения частоты и выход. Рабочая база не затрагивается.

Дополнительная браузерная проверка требует Playwright и Chromium (в приложении эти зависимости не нужны):

```sh
BASE_URL=http://127.0.0.1:8080 CHROMIUM_PATH=/usr/bin/chromium node tests/browser.cjs
```

Она использует тестовый адаптер YouTube, чтобы воспроизводимо проверить два браузерных контекста, управление, чат, восстановление сети и мобильную вёрстку. Это не проверка реального воспроизведения YouTube. Финальная проверка на реальных устройствах: открыть один зал в двух браузерах с доступом к YouTube, разрешить воспроизведение, проверить общую паузу/перемотку и возвращение после отключения сети.
