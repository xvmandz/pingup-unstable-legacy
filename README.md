# Вместе — один файл для вашего вечера

Всё приложение находится в **`index.php`**: интерфейс, мобильная вёрстка, стили, JavaScript, чат и PHP API. Папки `public`, `assets`, `src`, Composer, Node.js и отдельная установка базы не нужны.

## Установка на shared-хостинге

1. Скачайте `dist/vmeste-php.zip` и распакуйте на компьютере.
2. В панели хостинга выберите PHP **8.2 или новее**. Расширения **pdo_sqlite** и **mbstring** должны быть включены.
3. Загрузите **только `index.php`** в корневую папку сайта. Если корень уже настроен на `public`, загрузите файл прямо в эту `public`. Если корень указывает на каталог домена — положите файл туда. Перенастраивать корень сайта больше не требуется.
4. Откройте сайт по HTTPS. Обновите страницу через Ctrl + Shift + R.

Для существующей установки достаточно заменить `index.php` именно в текущем корне сайта. Старые `assets`, `src`, `scripts` и `tests` новой версии не нужны, но удалять свои данные для обновления не требуется. ZIP, README и исходные папки не нужно загружать на хостинг.

Если после загрузки виден PHP-код, а не сайт, остановитесь и включите обработку PHP для домена в панели. Если показано сообщение про расширения — включите их в настройках PHP.

## Как смотреть

Введите ник → создайте зал → «Пригласить» → отправьте ссылку девушке. Она открывает эту ссылку и вводит свой ник. Добавьте ссылку YouTube и нажмите ▶. Пауза и перемотка общие, чат рядом. На телефоне чат находится под плеером.

Браузер может потребовать нажатие «Включить у меня» для запуска со звуком на каждом устройстве. YouTube должен быть доступен вам обоим; видео должно разрешать встраивание. API-ключи не нужны.

Ссылка даёт доступ к залу и управлению видео — отправляйте её лично. Один браузерный профиль считается одним участником, поэтому для проверки вдвоём используйте два устройства или приватное окно.

## Данные

SQLite создаётся автоматически в отдельном каталоге `vmeste-…` во временной папке PHP **вне каталога сайта**. Создавать папки и выставлять права на каталог сайта не требуется. PHP должен иметь доступ на запись во временную папку и каталог сессий — обычно хостинг уже это обеспечивает.

Чат и состояние сохраняются между запросами и перезапусками PHP, пока хостинг не очистит временные файлы. Для просмотра на пару вечеров этого достаточно; долговременное хранение истории не гарантируется. При необходимости постоянного хранения администратор может задать `WATCH_DB` — абсолютный путь к SQLite вне публичного каталога, в существующей доступной на запись папке.

Обновление файла по тому же пути сохраняет данные. Перенос на другой путь создаёт отдельное хранилище; история предыдущей многофайловой версии автоматически не переносится.

## Что сохранено

Серверное состояние видео с версией команды, общая пауза и перемотка, исправление расхождения более 1,5 секунды, автоматическое переподключение, последние 300 сообщений, CSRF-защита, безопасный вывод текста, ограничения частоты запросов. Стили и скрипты встроены с CSP nonce, поэтому отдельные CSS/JS-файлы больше не могут потеряться при загрузке.

Сверка состояния происходит примерно раз в секунду, в фоновой вкладке — раз в четыре. Это не покадровая синхронизация. Прямые эфиры, плейлисты, реклама, платный контент и ограничения YouTube не синхронизируются и не обходятся. Встраивание реального YouTube требуется проверить на ваших устройствах: в cloud-окружении доступ к нему блокирует сетевой прокси.

## Разработка и проверки

На Debian 13 в cloud можно подготовить PHP командой `bash scripts/setup-cloud.sh`. Для обычного PHP это не требуется.

```sh
PHP_BIN=/workspace/php-runtime/bin/php python3 tests/integration.py
```

Тесты запускают отдельный сервер и копируют в пустой каталог **только `index.php`**. Проверяются чат, независимые сессии, пауза, перемотка, повторный просмотр, поздний вход, конфликт команд, валидация и защита запросов.

Для ручного запуска копируйте `index.php` в отдельный пустой каталог и запускайте оттуда встроенный PHP-сервер. Он предназначен для разработки, на shared-хостинге запускает PHP сам веб-сервер.

Опциональная браузерная проверка (Playwright и Chromium нужны только для теста):

```sh
BASE_URL=http://127.0.0.1:8081 CHROMIUM_PATH=/usr/bin/chromium node tests/browser.cjs
```

Тест проверяет два браузера, мобильную вёрстку и восстановление сети с тестовым адаптером YouTube; это не проверка реального видеовоспроизведения. При размещении в подпапке укажите её в BASE_URL, например `http://127.0.0.1:8081/pair/`.
